## Clase 1.3.1 — Descripción General

**Tipo:** 📄 Lectura — Soluciones de Seguridad Protego

### 💡 Ideas clave

- No es posible practicar en redes/aplicaciones de clientes reales.
- Se puede practicar en: **objetivos simulados**, redes con permiso de acceso, y ciertos sitios en la Internet abierta.
- Siempre hay que considerar la **legalidad** antes de usar herramientas de hacking ético en cualquier red.
- La VM de Kali Linux del curso incluye **redes IP internas simuladas** con sistemas intencionalmente vulnerables.

### ⚠️ Regla de oro
> Siempre prueba tus herramientas y técnicas en tu entorno de laboratorio **antes** de ejecutarlas en la red de un cliente. No hay garantía de que las herramientas no rompan algo — muchas están diseñadas precisamente para eso.

## Clase 1.3.2 — Requisitos y Pautas para el Laboratorio

**Tipo:** 📄 Lectura — Mejores prácticas

### ✅ Mejores prácticas para configurar un laboratorio de pentesting

| Requisito | Descripción |
|-----------|-------------|
| **Entorno virtualizado** | Usar VMs para aislar el entorno y poder revertir cambios |
| **Red cerrada / aislada** | Garantizar que el tráfico no salga hacia Internet o redes externas |
| **Recursos de hardware suficientes** | RAM, CPU y almacenamiento adecuados para resultados válidos |
| **Objetivos vulnerables** | Usar sistemas intencionalmente vulnerables (no hardened) para practicar |
| **Snapshots / respaldos** | Siempre tener un punto de restauración antes de cada prueba |

## Clase 1.3.4 — Práctica: Requisitos del Laboratorio

**Tipo:** ✅ Verificación de conocimientos

**Pregunta:** ¿Qué tres procedimientos recomendados seguirás al configurar tu laboratorio de pentesting?

> ✅ **Respuesta correcta:**
> - ✔️ Garantizar el acceso **cerrado** a la red e Internet → asegura control de acceso y restringe salida a Internet
> - ✔️ Crear un entorno informático **virtualizado** → facilita implementación y recuperación de dispositivos bajo prueba
> - ✔️ Proporcionar suficientes **recursos de hardware** → evita que la falta de recursos cause resultados falsos

> ❌ **Incorrectas:** usar la misma herramienta siempre · probar con un SO común · usar objetivos reforzados (hardened)

> 💡 Otras buenas prácticas adicionales: configuración realista, monitorear estado del sistema, usar múltiples SOs, duplicar herramientas de prueba y tener numerosos objetivos de práctica.

## Clase 1.3.5 — ¿Qué Pasa si Rompes Algo?

**Tipo:** 📄 Lectura

### ⚠️ El problema

Durante un pentest **siempre se rompen cosas**. Ejemplos:
- Ataques a apps web → datos falsos quedan en la base de datos
- Scripts maliciosos e inyecciones → pueden **corromper la base de datos**
- Sin método de recuperación → reconstruir el sistema desde cero = **pérdida de tiempo y dinero**

### 🔄 Soluciones de recuperación

| Escenario | Solución recomendada |
|-----------|---------------------|
| **Sistema virtualizable** | Usar **snapshots** (instantáneas) → restauración rápida al estado anterior |
| **Sistema no virtualizable** | Realizar una **copia de respaldo completa** antes de las pruebas |

> 💡 En un entorno de cliente, perder tiempo reconstruyendo sistemas **afecta el timeline** del proyecto.

#### 🔐 Privilegios de root

| Comando | Función |
|---------|---------|
| `sudo <comando>` | Ejecuta **un** comando con privilegios root (pide contraseña del usuario actual) |
| `su` | Cambia al usuario root completamente (pide contraseña de root) |
| `exit` | Sale del shell root y vuelve al usuario normal |
| `visudo` | Edita el archivo sudoers *(requiere sudo)* |
| `grep sudo /etc/group` | Verifica si el usuario está en el grupo sudo |

```bash
# Sin privilegios → error
$ visudo
visudo: /etc/sudoers: Permission denied

# Con sudo → funciona
$ sudo visudo

# Verificar grupo sudo
$ grep sudo /etc/group
sudo:x:27:kali        ← kali está en el grupo sudo
```

> 💡 `$` en el prompt = usuario normal · `#` en el prompt = usuario root

#### ⌨️ Atajos de teclado en la terminal

| Atajo | Función |
|-------|---------|
| `↑ / ↓` | Navegar por el historial de comandos |

#### 📁 Navegación y manejo de archivos

| Comando | Función |
|---------|---------|
| `pwd` | Muestra el directorio de trabajo actual |
| `ls` | Lista archivos y directorios |
| `ls -l` | Lista con detalles (permisos, tamaño, fecha) |
| `ls -la` | Lista con detalles + archivos ocultos |
| `cd <ruta>` | Cambia de directorio (ruta absoluta) |
| `cd ~` | Va al directorio home del usuario (`/home/kali`) |
| `cd .` | Permanece en el directorio actual (sin cambio visible) |
| `cd ..` | Sube un nivel al directorio padre |
| `mkdir <nombre>` | Crea un directorio |
| `mkdir a b c` | Crea múltiples directorios a la vez |
| `rm <archivo>` | Elimina un archivo |
| `rm -r <carpeta>` | Elimina una carpeta y todo su contenido (recursivo) |
| `mv <origen> <destino>` | Mueve archivo o carpeta (también sirve para renombrar) |
| `cat <archivo>` | Muestra el contenido de un archivo |
| `echo <texto>` | Imprime texto en la terminal |
| `man <comando>` | Muestra el manual del comando |

```bash
# Ejemplo navegación
$ pwd              → /home/kali
$ cd /home/kali/kali_folder3
$ pwd              → /home/kali/kali_folder3
$ cd ..            → /home/kali
$ cd ..            → /home
$ cd ..            → /        ← raíz, no sube más
$ cd ~             → /home/kali

# Rutas relativas: . y ..
.   = directorio actual
..  = directorio padre
```

#### 🔀 Redirección de salida

| Operador | Función |
|----------|---------|
| `>` | Redirige la salida a un archivo *(sobreescribe)* |
| `>>` | Redirige y **agrega** al final del archivo *(no sobreescribe)* |

```bash
$ echo redirect this to a file > text_file.txt
# (crea el archivo si no existe, sobreescribe si existe)

$ cat text_file.txt
redirect this to a file

$ echo this text will be appended >> text_file.txt

$ cat text_file.txt
redirect this to a file
this text will be appended
```

#### 🌐 SHODAN — Herramienta de reconocimiento pasivo

> Creada por **John Matherly** en 2009. Motor de búsqueda de dispositivos conectados a Internet.

**Usos en pentesting:**
- Escanear dispositivos del cliente que dan a Internet
- Ver qué información exponen los banners de los dispositivos
- Identificar vulnerabilidades CVE asociadas a esos dispositivos

**Filtros de búsqueda (sintaxis `filtro:valor`):**

| Filtro | Ejemplo | Resultado |
|--------|---------|-----------|
| `city:` | `webcam city:Toronto` | Webcams en Toronto |
| `port:` | `port:21` | Dispositivos con FTP abierto |
| `country:` | `country:US` | Dispositivos en EE.UU. |
| `product:` | `product:Apache port:80` | Servidores Apache en puerto 80 |

**Comandos CLI de Shodan:**
```bash
$ shodan init <API_KEY>     # Inicializa con tu clave API
$ shodan info               # Ver créditos disponibles
$ shodan myip               # Ver tu dirección IP pública
$ shodan search webcam      # Buscar (requiere créditos en cuenta gratuita)
```

> ⚠️ Siempre usar Shodan cumpliendo la **Declaración de Hacker Ético**. El acceso no autorizado a dispositivos encontrados en Shodan es ilegal.  
> 📌 Documentación: [help.shodan.io](https://help.shodan.io)
