### 💡 Proceso de reconocimiento activo

El reconocimiento activo se denomina **enumeración**. El flujo general es:

```
Identificar hosts expuestos a Internet
       ↓
Identificar servicios accesibles en esos hosts
       ↓
Escaneo de puertos → enumerar servicios en hosts expuestos
```

### 🔍 Escaneos de puertos — Concepto

Un escaneo de puertos envía sondeos a una IP y examina las respuestas para determinar si un servicio está escuchando.

**Escaneo SYN (-sS) — el más común:**

```
Attack System → SYN + Puerto → Target System
Attack System ← SYN/ACK ← Target System  (puerto ABIERTO)
Attack System → RST → Target System

Attack System → SYN + Puerto → Target System
Attack System ← TCP RST ← Target System   (puerto CERRADO)

Attack System → SYN + Puerto → Target System
(sin respuesta)                            (puerto FILTRADO)
```

**Tabla de estados Nmap (escaneo SYN):**

| Estado Nmap | Respuesta del objetivo | Análisis |
|------------|----------------------|----------|
| **Abierto** | TCP SYN-ACK | El servicio está escuchando en el puerto |
| **Cerrado** | TCP RST | El servicio no está escuchando |
| **Filtrado** | Sin respuesta o ICMP destino inaccesible | El puerto está protegido por firewall |

## Clase 3.2.2 — Tipos de Análisis de Nmap

**Tipo:** 📄 Lectura

### 📊 Tabla comparativa de tipos de escaneo

| Opción | Tipo de escaneo | Descripción |
|--------|-----------------|-------------|
| `-sS` | TCP SYN (semiabierto/stealth) | No completa el handshake → menos ruido, más difícil de detectar |
| `-sT` | TCP Connect | Conexión TCP completa → más ruido, más fácil de detectar |
| `-sU` | UDP | Busca puertos UDP (DNS, SNMP, DHCP) |
| `-sF` | TCP FIN | Envía paquete FIN para evadir firewalls |
| `-sn` | Detección de host (ping scan) | Solo detecta si el host está activo, sin escanear puertos |
| `-sV` | Detección de versiones | Sondea puertos abiertos para identificar servicio y versión |
| `-O` | Detección de SO | Identifica el sistema operativo |
| `-A` | Agresivo | Detección de SO + versiones + scripts + traceroute |
| `-sC` | Scripts por defecto NSE | Ejecuta los scripts NSE más comunes según puertos abiertos |
| `-p` | Puertos específicos | Especifica puertos o rangos a escanear |
| `-T <0-5>` | Temporización | Controla velocidad (0=lento/evasivo, 5=rápido/agresivo) |
| `-v` | Verboso | Muestra más información en pantalla |
| `--open` | Solo abiertos | Solo reporta puertos abiertos |

---

### 🔵 TCP SYN Scan (-sS)
```bash
nmap -sS 192.168.88.251
```
- Semiabierto — no completa el handshake TCP
- Menos detectable que `-sT`
- Requiere privilegios de root (paquetes raw)
- Puertos de muestra detectados: 22, 80, 139, 445, 3306, 8888, 9000, 9090

---

### 🟢 TCP Connect Scan (-sT)
```bash
nmap -sT 192.168.88.251
```
- Usa el mecanismo de red del SO para conexión completa
- **Más ruido** → activa más fácilmente los IDS
- Usar cuando no se tienen privilegios de paquetes raw

**Flujo TCP Connect:**
```
SYN → SYN/ACK → ACK → RST   (puerto abierto, luego cierra)
```

---

### 🟡 UDP Scan (-sU)
```bash
nmap -sU -p 53 192.168.88.251    # escanear puerto DNS
```

| Estado | Respuesta | Análisis |
|--------|-----------|----------|
| **Abierto** | Datos devueltos por el puerto | Servicio escuchando |
| **Cerrado** | Mensaje de error ICMP recibido | Sin servicio |
| **Abierto/Filtrado** | Sin respuesta ICMP | Firewall o timeout |

> ⚠️ Los mensajes ICMP inaccesibles pueden tener limitación de tasa → los escaneos UDP pueden ser muy lentos.

---

### 🔴 TCP FIN Scan (-sF)
```bash
nmap -sF -p 80 192.168.88.251
```
Envía paquete FIN — útil cuando un firewall detecta el escaneo SYN.

| Estado | Respuesta | Análisis |
|--------|-----------|----------|
| **Filtrado** | Error ICMP inaccesible | Puerto cerrado debe responder con RST |
| **Cerrado** | Paquete RST recibido | Puerto cerrado responde con RST |
| **Abierto/Filtrado** | Sin respuesta | Puerto abierto descarta el FIN |

```
FIN + Puerto → Target (sin respuesta) → puerto probablemente ABIERTO
FIN + Puerto → Target → RST → puerto probablemente CERRADO
```

> ⚠️ **No funciona bien en Windows** — responde con RST independientemente del estado del puerto.

---

### ⏱️ Opciones de Temporización (-T 0-5)

| Opción | Nombre | Descripción |
|--------|--------|-------------|
| `-T0` | Paranoico | Muy lento — evasión de IDS |
| `-T1` | Furtivo | Bastante lento — evasión de IDS |
| `-T2` | Educado | ~10x más lento que el default — menos ancho de banda |
| `-T3` | Normal | **Default** — modelo dinámico basado en respuesta del objetivo |
| `-T4` | Agresivo | Red rápida y confiable — puede abrumar al objetivo |
| `-T5` | Demente | Muy agresivo — puede perder puertos abiertos |

---

### 🔎 Host Discovery (-sn) — Ping Sweep

```bash
nmap -sn 192.168.88.0/24
```
- Envía: ping ICMP + TCP SYN al 443 + TCP ACK al 80 + ICMP timestamp
- Si el objetivo responde a cualquiera → host activo
- También llamado **barrido de ping**

## Clase 3.2.4 — Tipos de Enumeración

**Tipo:** 📄 Lectura + Ejemplos con Nmap y herramientas SMB

### 🖥️ Enumeración de Hosts
Primera tarea en la fase de recopilación de información.
- **Externa:** solo IPs en el alcance de la prueba (reduce riesgo de escanear fuera del alcance)
- **Interna:** normalmente la subred completa del objetivo

```bash
nmap -sn 192.168.88.0/24   # ping sweep completo
```

---

### 👤 Enumeración de Usuarios — SMB

**Protocolo SMB** (puerto TCP 445) — intercambia mensajes entre cliente y servidor:

```
Cliente → SMB_COM_NEGOTIATE (Request) → Servidor
Cliente ← SMB_COM_NEGOTIATE (Response) ← Servidor
Cliente → SMB_COM_SESSION_SETUP_ANDX (Request + credenciales) → Servidor
Cliente ← SMB_COM_SESSION_SETUP_ANDX (Response) ← Servidor
Cliente → SMB_COM_TREE_CONNECT_ANDX (Request) → Servidor
Cliente ← SMB_COM_TREE_CONNECT_ANDX (Response) ← Servidor
```

**Script NSE para enumeración de usuarios:**
```bash
nmap --script smb-enum-users.nse 192.168.88.251
```
Resultado: enumera usuarios como `VULNHOST-1\derek (RID: 1000)`

---

### 👥 Enumeración de Grupos

```bash
nmap --script smb-enum-groups.nse -p445 192.168.56.3
# Con credenciales conocidas:
nmap --script smb-enum-groups.nse --script-args smbusername=vagrant,smbpass=vagrant 192.168.56.3
```

> En Windows, el **RID (Relative Identifier)** es un número que forma parte del **SID (Security Identifier)** que identifica una cuenta o grupo en el dominio.

---

### 📂 Enumeración de Recursos Compartidos de Red

```bash
nmap --script smb-enum-shares.nse -p 445 192.168.88.251
```

Resultado de ejemplo:
```
\\192.168.88.251\IPC$:        Anonymous access: READ/WRITE  ← PELIGRO
\\192.168.88.251\print$:      Anonymous access: <none>
\\192.168.88.251\secret_folder: Anonymous access: <none>
               Comment: Extremely sensitive information
```

---

### 🔧 Herramientas adicionales de enumeración SMB

#### enum4linux
```bash
enum4linux 192.168.88.251
```
Obtiene: versión de Samba, usuarios, grupos, recursos compartidos, política de contraseñas.

#### enum4linux-ng (versión Python)
```bash
./enum4linux-ng.py -As 192.168.88.251
```
URL: github.com/cddmp/enum4linux-ng

#### smbclient
```bash
smbclient -L \\\\192.168.88.251
```

#### Scripts NSE por defecto (-sC)
```bash
nmap -sC 192.168.88.251
```
Ejecuta automáticamente los scripts NSE más comunes según los puertos abiertos. Detecta: versión de Samba, usuarios NetBIOS, modo de seguridad SMB.

> 📌 Localizar scripts NSE instalados en Kali: `locate *.nse`

---

### 🌐 Enumeración de Páginas Web / Aplicaciones Web

```bash
# Nmap http-enum — fuerza rutas de directorios conocidas
nmap -sV --script=http-enum -p 80 192.168.88.251
```
Resultado: encuentra `/admin/`, `/admin/index.html`, `/s/` y versión del servidor (nginx 1.17.2)

```bash
# Nikto — escáner web de código abierto
nikto -h 192.168.88.251
```
Resultado: detecta falta de headers de seguridad (X-Frame-Options, X-XSS-Protection), páginas admin expuestas, versión del servidor.

> ⚠️ **Nikto es muy "ruidoso"** — genera mucho tráfico y es fácilmente detectable.

### 📦 Elaboración de Paquetes con Scapy

**Scapy** = framework Python para generación y manipulación de paquetes. Creado por Philippe Biondi.

**Iniciar Scapy (requiere root):**
```bash
sudo su
scapy
```

**Funciones principales:**

| Función | Descripción |
|---------|-------------|
| `ls()` | Lista todos los formatos y protocolos disponibles |
| `ls(TCP)` | Lista campos de un protocolo específico |
| `ls(IP)` | Campos del encabezado IPv4 |
| `explore()` | Navegar por capas y protocolos |
| `explore("dns")` | Ver tipos de paquetes DNS |
| `send()` | Enviar un paquete |
| `sr()` | Enviar y recibir (send/receive) |
| `sniff()` | Capturar tráfico |
| `sniff(iface="br-internal")` | Capturar en interfaz específica |
| `sniff(filter="icmp", count=10)` | Filtrar por protocolo y limitar cantidad |
| `wrpcap("archivo.pcap", var)` | Guardar captura en archivo PCAP |
| `a.summary()` | Ver resumen de captura |
| `a.nsummary()` | Ver resumen con números de línea |

**Campos IPv4 en Scapy:**
```
version, ihl, tos, len, id, flags, frag, ttl, proto, chksum, src, dst, options
```

**Crear paquete ICMP personalizado:**
```python
>>> send(IP(dst="192.168.88.251")/ICMP()/"malicious_payload")
```

**Crear paquete TCP SYN:**
```python
>>> ans, unans = sr(IP(dst='192.168.88.251')/TCP(dport=445, flags='S'))
```

**Respuesta SYN-ACK indica puerto abierto:**
```
192.168.78.142 → 192.168.88.251  TCP [SYN]
192.168.88.251 → 192.168.78.142  TCP [SYN, ACK]  ← puerto 445 ABIERTO
192.168.78.142 → 192.168.88.251  TCP [RST]
```

**¿Cómo puede usarse para DoS?** Enviar miles de paquetes ICMP con IP origen falsificada → todas las respuestas van a la víctima falsa → DDoS reflejado.

## Clase 3.2.9 — Laboratorio: Elaboración de Paquetes con Scapy

**Tipo:** 🧪 Laboratorio — Scapy en Kali

### 🔑 Conceptos clave del lab

**¿Cómo describe Philippe Biondi a Scapy?**
> "Scapy es un programa Python que permite al usuario enviar, rastrear, diseccionar y falsificar paquetes de red. Esta capacidad permite la construcción de herramientas que pueden sondear, escanear o atacar redes."

**Formatos TFTP en Scapy:** 9 tipos

**Flujo de captura con Scapy:**
```python
>>> sniff()                                    # captura en eth0
>>> sniff(iface="br-internal")                 # interfaz específica
>>> sniff(iface="br-internal", filter="icmp", count=10)  # filtrado
>>> a = _                                      # guardar resultado
>>> a.summary()                                # ver resumen
>>> a.nsummary()                               # con números de línea
>>> a[2]                                       # ver paquete específico
>>> wrpcap("capture1.pcap", a)                 # guardar en PCAP
```

**Diferencia en dos conjuntos de src/dst:**
> El primero = MACs de capa 2 (Ethernet) · El segundo = IPs de capa 3 (Red)

**Diferencia entre ICMP original y personalizado:**
> El paquete personalizado incluye una carga útil (payload) modificada en el campo `load=`

**Respuesta SYN-ACK (`flags=SA`) al enviar al puerto 445:**
> Significa que el puerto 445 está **abierto** y aceptando conexiones

## Clase 3.2.10 — Laboratorio: Rastreo de Redes con Wireshark

**Tipo:** 🧪 Laboratorio — tcpdump + Wireshark

### 💻 Comandos del laboratorio

```bash
# Ver directorio actual
pwd                           # → /home/kali

# Ver interfaces de red
ifconfig
ip route                      # ver gateway predeterminado
cat /etc/resolv.conf          # ver DNS configurado

# Capturar tráfico con tcpdump
sudo tcpdump -i eth0 -s 0 -w packetdump.pcap
# -i eth0 = interfaz a capturar
# -s 0    = captura 262144 bytes por paquete (default completo)
# -w      = escribir a archivo
# CTRL-C para detener

# Verificar que el archivo existe
ls packetdump.pcap

# Abrir Wireshark
wireshark
wireshark packetdump.pcap
```

### 🔍 Análisis en Wireshark

**Filtros útiles:**
- `dns` → solo tráfico DNS
- Buscar cadena: Ctrl+F → "String" → ingresar término

**Información que revela el tráfico DNS:**
- Sitios web visitados (google.com, youtube.com, facebook.com, doubleclick.net, cisco.com)
- Direcciones IP de los sitios
- Servidores DNS usados

**En sesión HTTP (sin cifrado) se puede ver:**
- Nombre de usuario y contraseña en texto plano (en paquetes POST)
- Cookies de sesión (PHPSESSID)
- Token de usuario

> ⚠️ El servidor DVWA usa HTTP (no HTTPS) → las credenciales viajan **sin cifrar**.
