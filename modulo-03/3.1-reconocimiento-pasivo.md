## Clase 3.1.2 — Reconocimiento Activo vs. Reconocimiento Pasivo

### ⚔️ Comparativa

| | Reconocimiento Activo | Reconocimiento Pasivo |
|-|-----------------------|-----------------------|
| **Definición** | Envía sondas directamente al objetivo | No interactúa con el objetivo |
| **Detección** | Puede ser detectado | Muy difícil de detectar |
| **Riesgo** | Puede bloquear dispositivos frágiles | Sin interrupciones |
| **Uso ideal** | Con permiso del cliente | En redes de producción sensibles |

### 🔵 Métodos Activos
Enumeración de: hosts · redes · usuarios · grupos · recursos compartidos · páginas web · aplicaciones · servicios · Elaboración de paquetes

### 🟢 Métodos Pasivos
Enumeración de dominios · Inspección de paquetes · OSINT · Recon-ng · Intercepción pasiva

## Clase 3.1.5 — Búsquedas de DNS

### 🛠️ Herramientas y comandos

#### DNSRecon
```bash
dnsrecon -d h4cker.org
# Enumera: DNSSEC, SOA, NS, MX, A, SPF, TXT
```

#### dig
```bash
dig h4cker.org              # Registros A (IPv4) — por defecto
dig h4cker.org AAAA         # IPv6
dig h4cker.org mx           # Servidores de correo
dig h4cker.org ns           # Servidores de nombres
dig h4cker.org any          # Todos los tipos
dig h4cker.org @8.8.8.8 ns  # Usar servidor DNS específico
dig -x 72.163.5.201         # DNS inverso → registro PTR
```

#### nslookup
```bash
nslookup                    # Modo interactivo
> cisco.com                 # Registros A y AAAA (por defecto)
> set type=ns               # Cambiar a servidores de nombres
> set type=mx               # Cambiar a servidores de correo
> set type=any              # Todos los tipos
> server 8.8.8.8            # Usar DNS de Google
> exit

nslookup netacad.com 8.8.8.8       # No interactivo con servidor específico
nslookup 72.163.5.201              # DNS inverso
```

#### host
```bash
host 72.163.10.1            # DNS inverso — salida breve
host hsrp-72-163-10-1.cisco.com
```

**Tipos de registros DNS:**

| Tipo | Descripción |
|------|-------------|
| **A** | Dirección IPv4 |
| **AAAA** | Dirección IPv6 |
| **NS** | Servidores de nombres |
| **MX** | Servidores de correo |
| **SOA** | Start of Authority |
| **TXT** | Texto / verificaciones SPF, DKIM |
| **PTR** | DNS inverso (IP → nombre de host) |

**Comparativa de herramientas:**

| Herramienta | Por defecto | Salida | Mejor para |
|-------------|-------------|--------|-----------|
| `dig` | Solo A | Técnica y detallada | Detalle técnico |
| `nslookup` | A y AAAA | Más simple | Principiantes |
| `host` | Resolución simple | Muy breve | Consultas rápidas |

## Clase 3.1.10 — Aplicaciones en la Nube vs. Servidores Propios y Subdominios

**Tipo:** 📄 Lectura

### 💡 Concepto clave

Una empresa puede poseer un dominio pero tener sus aplicaciones alojadas en la nube. Ejemplo: Netflix usa IPs de **AWS** aunque el dominio es `netflix.com`.

```bash
# Verificar dueño real de las IPs de un dominio
host netflix.com                          # obtiene IPs
whois 3.230.129.93 | grep OrgName         # → Amazon Technologies Inc.
whois 52.3.144.142 | grep OrgName         # → Amazon Technologies Inc.
```

> 💡 Durante el reconocimiento, identificar al proveedor de nube ayuda a entender restricciones de prueba (los CSPs tienen sus propias políticas de pentest) y a preparar ataques dirigidos.

**Tipo:** 📄 Lectura

### 🎯 Información valiosa en redes sociales

Los atacantes rastrean: Twitter · LinkedIn · Facebook · Instagram

## Clase 3.1.12 — Laboratorio: Recopilación de Inteligencia de los Empleados

**Tipo:** 🧪 Laboratorio — Redes sociales y PII

### 🎯 Objetivos
- Recopilar PII desde redes sociales (investigando el propio perfil)
- Reflexionar sobre los riesgos de la exposición en redes sociales

### 📋 Información que puede revelarse en redes sociales

- Nombre completo, fecha de nacimiento, información de contacto
- Lugar de trabajo, cargo, tecnologías usadas
- Agenda diaria, planes de vacaciones, ubicación geográfica
- Creencias políticas/religiosas, intereses, pasatiempos
- Miembros de la familia, mascotas (útiles para adivinar contraseñas)
- Conversaciones públicas con amigos y familiares

### 🔓 ¿Cómo puede usar esta info un ciberdelincuente?

| Información | Uso malicioso |
|-------------|---------------|
| Lugar de trabajo | Phishing/whaling suplantando a la empresa |
| Pasatiempos e intereses | Páginas falsas relacionadas con sus gustos → instala malware / roba credenciales |
| Conversaciones públicas | Obtener respuestas a preguntas de seguridad · suplantación de identidad |

### 💡 Mejores prácticas en redes sociales

1. Configurar cuentas como **privadas**
2. No publicar información en tiempo real (ubicación, viajes)
3. Usar **contraseñas seguras y 2FA**
4. Revisar periódicamente etiquetas y menciones
5. Solo aceptar solicitudes de personas conocidas
6. Pensar antes de publicar información personal o laboral
7. Limitar la información visible públicamente en perfiles

### ✅ Verificación de habilidades
**Nivel de riesgo del perfil de redes sociales (escala 1-10):** → 2 (perfil con mínima información pública)

## Clase 3.1.13 — Fallas Criptográficas

**Tipo:** 📄 Lectura

### 🔐 Certificados SSL/TLS como fuente de reconocimiento

Durante el reconocimiento, los atacantes inspeccionan certificados digitales para obtener:
- Número de serie del certificado
- Nombre común del sujeto (CN)
- URI del servidor asignado
- Nombre de la organización
- Información OCSP y CRL
- Subdominios adicionales (mediante **transparencia de certificados**)

### 📋 Conceptos clave

| Concepto | Descripción |
|----------|-------------|
| **SSL/TLS** | Cifra la comunicación entre cliente y servidor |
| **X.509** | Estándar que define el formato de los certificados de clave pública |
| **Revocación de certificados** | Invalidación de un certificado digital |
| **CRL** | Lista de revocación de certificados |
| **OCSP** | Protocolo para verificar si un certificado ha sido revocado |
| **Transparencia de certificados (CT)** | Sistema que permite verificar públicamente la emisión de certificados digitales |

### 🌐 Herramientas para análisis de certificados

| Herramienta | URL | Función |
|-------------|-----|---------|
| **crt.sh** | crt.sh | Consulta transparencia de certificados → revela subdominios adicionales |
| **CertSpotter** | — | Monitoreo automatizado de registros CT |
| **Censys** | censys.io | Búsqueda en registros CT |

**Ejemplo:** `https://crt.sh/?q=h4cker.org` → muestra todos los certificados emitidos + subdominios desconocidos

> 💡 La **transparencia de certificados** fue creada tras el ataque a DigiNotar, para detectar mejor la emisión de certificados maliciosos.

## Clase 3.1.14 — Laboratorio: Búsqueda de Información desde Certificados SSL

**Tipo:** 🧪 Laboratorio — sslscan + crt.sh

### 🛠️ Herramientas SSL en Kali

| Herramienta | Descripción | Uso |
|-------------|-------------|-----|
| **sslscan** | Consulta servicios SSL para determinar cifrados admitidos | Reconocimiento |
| **ssldump** | Analiza y decodifica tráfico SSL | Explotación |
| **sslh** | Ejecuta varios servicios en el puerto 443 | Utilidad |
| **sslsplit** | Habilita ataques MitM en conexiones SSL | Explotación |
| **sslyze** | Analiza la configuración SSL de un servidor | Reconocimiento |

### 💻 Comandos del laboratorio

```bash
# Ejecutar sslscan
sslscan netacad.com

# Guardar resultado en HTML (con colores)
sudo apt update && sudo apt install -y aha
sslscan netacad.com | aha > sfa_cert.html

# Abrir resultado en Firefox
firefox sfa_cert.html
```

**Código de colores de sslscan:**
- 🔴 Fondo rojo: cifrado NULO (sin cifrado)
- 🔴 Rojo: cifrado roto (≤40 bits) o protocolo vulnerable (SSLv2/SSLv3) o firma MD5
- 🟡 Amarillo: cifrado débil (≤56 bits) o firma SHA-1
- 🟣 Violeta: cifrado anónimo (ADH/AECDH)

### 📋 Respuestas del laboratorio — Certificados

| Pregunta | Respuesta |
|----------|-----------|
| ¿Para qué dominio se emitió el cert de netacad.com? | socialgoodplatform.com — emitido por IdenTrust |
| ¿Algoritmo de cifrado? | SHA-256 con RSA (sha256RSA) |
| Certificados raíz comunes en Kali | DigiCert · Sectigo · Let's Encrypt |
| Costo SSL básico anual | Let's Encrypt: gratis · Sectigo: $10-80 · DigiCert: $200-400 |
| ¿Qué revela crt.sh de netacad.com? | Subdominios para dev, stage, APIs, servicios internos, etc. |
| ¿Qué otro dominio asociado aparece? | socialgoodplatform.com |
| ¿Qué dice la búsqueda de socialgoodplatform? | Gran cantidad de subdominios → gran superficie de ataque |
| Herramienta más útil del lab | crt.sh (más detallada para OSINT); sslscan/sslyze para auditoría técnica |

### 📸 ExifTool — Metadatos de archivos

ExifTool lee metadatos de: imágenes (JPG, PNG, TIFF), documentos (PDF, DOC), audio (MP3, WAV), video (MP4, MOV), archivos (ZIP, RAR).

**Datos Exif que pueden revelarse:**
- Fabricante y modelo del dispositivo (ej: iPhone 12 Pro Max)
- Fecha y hora de creación
- **Coordenadas GPS** (latitud y longitud)
- Software utilizado
- Nombre del autor / organización

```bash
exiftool IMG_4730.jpg            # metadata de un archivo
exiftool /carpeta/               # metadata de toda una carpeta
exiftool -csv > out.csv /carpeta # exportar a CSV
exiftool -listf                  # ver tipos de archivo compatibles
```

### 🔎 Google Dorking — Operadores avanzados

| Operador | Función | Ejemplo |
|----------|---------|---------|
| `site:` | Solo resultados de ese dominio | `site:empresa.com` |
| `filetype:` | Solo ese tipo de archivo | `filetype:pdf` |
| `inurl:` | Término en la URL | `inurl:admin` |
| `intitle:` | Término en el título | `intitle:login` |
| `intext:` | Término en el texto | `intext:password` |
| `allintext:` | Todas las palabras en el texto | |
| `link:` | Páginas que enlazan al dominio | `link:www.empresa.com` |

**Ejemplo de dork para buscar IDs de sesión expuestos:**
```
intext:JSESSIONID OR intext:PHPSESSID inurl:access.log ext:log
```

**Ejemplo de dork para contraseñas en código:**
```
"public $user =" | "public $password =" | "public $secret =" ext:txt | ext:log -git
```

> 📌 Google Hacking Database (GHDB): [exploit-db.com/google-hacking-database](https://www.exploit-db.com/google-hacking-database/)

**Categorías de GHDB:** Puntos de apoyo · Archivos con usernames · Directorios sensibles · Detección de servidores web · Archivos con contraseñas · Páginas de login · Dispositivos varios en línea · Mensajes de error · y más.

### 🕰️ Wayback Machine (archive.org/web)

Permite ver versiones históricas de sitios web. Pestañas disponibles:
- **Calendario:** snapshots por fecha
- **Colecciones:** organizadas por fuente
- **Changes:** muestra cuánto cambió la página
- **Summary:** tipos MIME del contenido del dominio
- **Site Map:** mapa visual de la estructura del sitio
- **URL:** todas las URLs rastreadas del dominio (buscar `.bak`, `.config`, `/admin/`)

**¿Por qué es útil para un atacante?**
- Ver información eliminada o ya no pública
- Encontrar páginas/directorios ocultos
- Descubrir tecnologías antiguas y vulnerables
- Obtener datos de versiones pasadas para ingeniería social

## Clase 3.1.19 — Laboratorio: Búsquedas Avanzadas

**Tipo:** 🧪 Laboratorio — Google Dorking + GHDB + Wayback Machine

### 📋 Operadores avanzados de Google

| Operador | Ejemplo | Resultado |
|----------|---------|-----------|
| `site:` | `ethical hacker site:pearson.com` | Solo resultados de ese dominio |
| `filetype:` | `site:pearson.com filetype:pdf` | Solo archivos PDF |
| `intitle:` | `ethical hacker intitle:certification` | La palabra en el título de la página |
| `inurl:` | `ethics hacker inurl:free` | La palabra en la URL |
| `allintext:` | `allintext:free ethical hacker test` | Todas las palabras en el texto |
| `intext:` | `intext:employee` | Término específico en el texto |

**Búsquedas útiles para reconocimiento:**
```
site:empresa.com inurl:admin
site:empresa.com intitle:login
site:empresa.com filetype:pdf
site:empresa.com intext:employee filetype:pdf
site:linkedin.com intitle:"nombre empresa"
```

**¿Qué información puede obtener un hacker de LinkedIn con dorking?**
> Nombres de empleados, cargos, estructura organizacional, correos, tecnologías usadas, ubicaciones → facilita ataques de ingeniería social.

### 🗃️ Google Hacking Database (GHDB)

Índice comunitario de dorks para descubrir información confidencial expuesta accidentalmente.

**Información en cada dork:** ID GHDB · autor · fecha · descripción · enlace para ejecutarlo  
**Búsqueda `allinurl:tsweb/default.htm`** → páginas de login de Terminal Services/Remote Desktop (Windows Server antiguo)  
**Categoría `Files Containing Passwords` + búsqueda `db_pass`** → contraseñas de bases de datos expuestas

### 🕰️ Wayback Machine (archive.org/web)

| Pestaña | Función |
|---------|---------|
| **Calendario** | Snapshots del sitio por fecha |
| **Colecciones** | Archivos organizados por fuente rastreadora |
| **Changes** | Gris = poco cambio · Azul = cambios significativos |
| **Summary** | Tipos MIME del contenido del dominio completo |
| **Site Map** | Mapa visual de la estructura del sitio (círculos concéntricos) |
| **URL** | Todas las URLs rastreadas — filtros útiles: `.bak`, `.config`, `.csv`, `/admin/`, `/api/` |

**¿Por qué es valiosa para el reconocimiento?**
> Permite descubrir información eliminada, páginas ocultas, tecnologías antiguas vulnerables y datos útiles para ingeniería social, **sin interactuar con el sistema objetivo**.

### 💭 Reflexión del laboratorio
**¿Por qué el reconocimiento pasivo es tan importante?**
> Permite recopilar información sobre el objetivo sin interactuar con sus sistemas → reduce la probabilidad de ser detectado → ayuda a identificar vulnerabilidades y planificar mejor las pruebas.

### ✅ Verificación de habilidades
**¿Qué es cierto sobre `inurl:"/private" intext:"index of /" "win64" -litespeed`?**
> ✅ Devuelve páginas con "/private" en la URL  
> ✅ Devuelve páginas con "index of /" **y** "win64" en el texto  
> ✅ NO incluye páginas con "litespeed" (el `-` lo excluye)  
> ❌ No devuelve solo archivos de servidores Windows de 64 bits (es una búsqueda de texto, no de archivos)

## Clase 3.1.20 — Recopilación de OSINT

**Tipo:** 📄 Lectura

### 📌 OSINT — Definición

> **OSINT (Open Source Intelligence):** método de recopilación de fuentes disponibles públicamente para recopilar y analizar información sobre un objetivo. No requiere métodos encubiertos.

Cuanto mayor sea la presencia en línea del objetivo, más información disponible. Una búsqueda en Google puede ser el punto de partida suficiente para orientar todo el proceso.

### 🔁 Recon-ng — Flujo de trabajo completo

Desarrollado por **Tim Tomes (Black Hills Information Security)** en Python, inspirado en Metasploit msfconsole. Eficaz en **enumeración de redes sociales** mediante APIs. Incluye función de **exportación de informes** en múltiples formatos.

**Módulos de reporting disponibles:**
`reporting/csv` · `reporting/html` · `reporting/json` · `reporting/list` · `reporting/xlsx` · `reporting/xml`

**Flujo de trabajo paso a paso:**

```bash
# Paso 1: Iniciar
recon-ng

# Paso 2: Ver comandos disponibles
help

# Paso 3: Ver módulos del marketplace
marketplace search

# Paso 4: Actualizar marketplace
marketplace refresh

# Paso 5: Buscar módulo específico
marketplace search bing

# Paso 6: Instalar módulo
marketplace install recon/domains-hosts/bing_domain_web

# Paso 7: Ver módulos instalados
modules search

# Paso 8: Cargar módulo
modules load recon/domains-hosts/bing_domain_web

# Paso 9: Configurar dominio objetivo
options set SOURCE h4cker.org

# Ejecutar
run
```

**Resultado del ejemplo (h4cker.org con bing_domain_web):**
Subdominios encontrados: `bootcamp.h4cker.org` · `webapps.h4cker.org` · `lpb.h4cker.org` · `malicious.h4cker.org`

**Columnas del marketplace:**
- `D` = tiene dependencias (módulos Python adicionales)
- `K` = requiere clave de API

**Sitios que Recon-ng puede consultar via API:** Facebook · Indeed · Flickr · Instagram · Shodan · LinkedIn · YouTube · Censys

> 💡 Combina módulos: usa `recon/domains-hosts/brute_hosts` con listas de palabras para encontrar subdominios adicionales mediante fuerza bruta de DNS.

### 🔭 Shodan — Introducción

Motor de búsqueda de dispositivos conectados a Internet creado por **John Matherly (2009)**. Escanea Internet 24/7 y almacena los resultados en una base de datos consultable en shodan.io o via API.

**Unidad fundamental de datos:** el **banner** (información que expone un dispositivo al responder a una conexión).

**Categorías exploradas en Shodan:**
Industrial Control Systems (ICS) · Databases · Network Infrastructure · Video Games

**Ejemplo real:** búsqueda `cisco smart install` → 15,174 dispositivos con protocolo vulnerable activo (Cisco retiró este protocolo pero aún hay dispositivos expuestos).

## Clase 3.1.21 — Laboratorio: Búsquedas de Shodan

**Tipo:** 🧪 Laboratorio — Shodan web + CLI

### 🎯 Objetivos
- Crear cuenta y obtener clave de API de Shodan
- Buscar dispositivos IoT vulnerables en la web de Shodan
- Usar Shodan desde la CLI de Kali

### 🌐 Parte 1 — Cuenta y API

```bash
# Inicializar Shodan con clave API
shodan init <tu-clave-api>
# → "Successfully initialized"
```

### 🔍 Parte 2 — Búsquedas en la web

**Búsqueda básica:** `webcam` → devuelve todos los dispositivos con "webcam" en su banner de servicio (no necesariamente cámaras web)

**Información en la sección General de un dispositivo:**
- Dirección IP · nombre de host · dominio
- País, ciudad, organización, ISP, ASN
- Última vez visto
- Puertos abiertos + banner de cada servicio
- Vulnerabilidades CVE (cuando las hay)

**Filtros de Shodan (sintaxis `filtro:valor`):**

| Filtro | Ejemplo | Función |
|--------|---------|---------|
| `country:` | `country:US` | Filtra por país (código 2 letras) |
| `city:` | `city:Toronto` | Filtra por ciudad |
| `region:` | `region:CA` | Filtra por estado/región |
| `product:` | `product:Apache` | Filtra por producto |
| `version:` | `version:2.4` | Filtra por versión |
| `vuln:` | `vuln:CVE-2021-44228` | Filtra por número CVE |
| `port:` | `port:21` | Filtra por puerto |

**Ejemplos de búsquedas:**
```
webcam city:Toronto
port:21 country:US region:CA city:"San Jose" 230    # FTP con login anónimo
Apache port:80 city:"tu-ciudad"
cisco smart install                                  # protocolo vulnerable
```

**País con más cámaras web:** Estados Unidos  
**Resultado FTP anónimos en San José (al momento del curso):** ~847 servidores

**Etiquetas especiales en resultados:** `cloud` (incluye proveedor, región y servicio de nube) · `honeypot`

### 💻 Parte 3 — Shodan en CLI

```bash
shodan init <api-key>        # inicializar con clave API
shodan -h                    # ver todos los comandos
shodan search webcam         # buscar (requiere créditos en cuenta gratuita)
shodan info                  # ver créditos disponibles
shodan myip                  # ver tu IP pública
shodan stats webcam          # estadísticas de resumen de una búsqueda
```

> ⚠️ Las búsquedas con filtros **no están disponibles** con clave API gratuita (error 403).  
> Con cuenta académica (.edu): 16 IPs monitoreadas, 100 consultas/mes, 100 escaneos/mes.

### 💡 ¿Para qué es especialmente valiosa Shodan en pentesting?

- Escanear dominios y subdominios del cliente que dan a Internet
- Ver qué información exponen los banners de los dispositivos
- Identificar vulnerabilidades CVE en servicios expuestos
- Descubrir configuraciones incorrectas (FTP anónimo, credenciales por defecto)
- Detectar protocolos inseguros aún en uso (ej: Cisco Smart Install)

> ⚠️ Aunque es información pública, **no interactúes** con sistemas encontrados en Shodan sin permiso del propietario. Si hay un programa de bug bounty, reporta la vulnerabilidad para obtener reconocimiento/recompensa.

### ✅ Verificación de habilidades
**¿Qué es cierto sobre buscar "cámara web" en Shodan?**
> ✅ Devolverá **todos los dispositivos** que incluyan el término "cámara web" en sus banners de servicio (no solo cámaras web reales).
